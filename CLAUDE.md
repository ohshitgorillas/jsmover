# jsmover — agent rules

- **Gate exemptions are owner-approved (hard rule).** A gate says no; the fix is the code. Every exemption (inline `eslint-disable`, `@ts-ignore` or `@ts-expect-error`, a knip `ignore`/`ignoreDependencies` entry, a jscpd `ignore` path, a filepawl `exempt` entry or accepted allowance, a triviajudge `excluded` path, a raised or lowered threshold, a skipped test, a deviation from `docs/testing.md`) ships only with owner approval of that specific site, granted before it is written; proposing one names the gate, the site, why the code cannot satisfy it and what it costs. Widening one, or one written by a subagent, is a new exemption. Removal needs no approval.
- **Commit without asking; never push without asking.** `git push` and any remote operation happen on the owner's word alone.
- **`make check` green before every commit**; pre-commit runs the same gates in full. `--no-verify`, `SKIP=` and hook-config edits stay off the table.
- **Every gate run goes through `scripts/gate.sh`** — `scripts/gate.sh make check`, `scripts/gate.sh make test-js`. It keeps the whole log under `${CLAUDE_SCRATCH:-/tmp}`, prints `exit=<rc> log=<path>`, and selects the failure lines by pattern rather than by position: up to 40 matched lines on red, three tail lines on green, and the wrapped command's own exit status. When the matched lines do not settle it, read the log at the printed path. A gate is never piped into `head`, `tail` or `grep` or sent to `/dev/null`.
- **Tests for new or changed behavior are written tests-first**, and a red run against the pre-change code is the bite proof (`docs/testing.md` rule 8). A red test after implementation has two outcomes and no third: fix the code, or take the change back to the owner. Tests are never edited to pass. Testing policy binding: `docs/testing.md`.
- **Markdown is soft-wrapped**: one paragraph, list item or blockquote per logical line, written with `Write`/`Edit`, never from the shell.
- **Trivia gets cut.** Project trivia and decision archaeology do not belong in documentation or in comments at any level; decisions go in the commit message. Enforced by the `triviajudge` plugin and package, scoped by `[tool.triviajudge]` in `pyproject.toml`: the plugin's hooks judge every added markdown line and screen every added comment, and its console scripts run at commit and over HEAD (`.venv/bin/triviajudge-md`, `-comments`, `-changelog`, `-archaeology`, `make trivia`).
